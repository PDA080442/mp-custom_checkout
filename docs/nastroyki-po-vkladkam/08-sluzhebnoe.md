# Вкладка «Служебное»

Здесь собраны **режимы для тестирования**, **переключатели функций** и **проверка здоровья** checkout. Часть блоков может отображаться **дополнительно** внизу страницы (например **Feature flags** и **Step Registry**).

---

## Тестовый режим (`testing_mode_toggle` и `testing_scenarios`)

- **`testing_mode_toggle`** — включает ли плагин **упрощённые тестовые сценарии** для проверки витрины без реальных заказов (значение по умолчанию в коде может быть `true` для удобства разработки — **на продакшене уточните у разработчика**, нужно ли отключать).

- **`testing_scenarios`** — какие «заготовки» подставлять для автопроверок:
  - `default_sandbox` — имя сценария песочницы, например `pickup_happy_path`.
  - `step_scenarios` — какой сценарий привязан к шагам `step_1` … `step_4` (например `cart_review`, `date_available` …).

**Важно:** тестовый режим может **менять поведение оплаты** или обходить часть проверок. На живом магазине держите выключенным, если так сказано в политике безопасности.

---

## Утилиты тестирования (`test_utilities`)

### `fulfillment`

Галочки: включена ли симуляция для **самовывоза**, **доставки по городу**, **доставки в другой город**. Используется для внутренних проверок / превью.

### `discounts`

Включение сценариев: успех/отказ купона, успех/отказ подарочной карты — для **отладки интерфейса**, не для реальных скидок.

### `validation_payment`

Показ **ошибок валидации**, индикаторов загрузки оплаты, успеха/ошибки оплаты — удобно при съёмке скриншотов или обучении поддержки.

---

## Проверка здоровья (`health_checks`)

- `enabled` — включить ли блок **Health Checks** на этой вкладке.

Внизу страницы может появиться сводка: сколько проверок **OK / WARN / FAIL**. При FAIL читайте текст и передавайте в поддержку или разработчику.

---

## Блок «Feature flags» (дополнительно на этой вкладке)

Это **глобальные переключатели функций**. Имена из кода:

| Флаг | По умолчанию | Что обычно означает |
|------|----------------|---------------------|
| `custom_checkout_route` | вкл. | Использовать **кастомный маршрут** checkout плагина. |
| `multi_step_flow` | вкл. | **Многошаговый** сценарий. |
| `multi_pickup_points` | выкл. | Несколько **точек магазинного самовывоза** (`pickup`), если доработано — **не** относится к ПВЗ СДЭК. |
| `pvz_office_required` | вкл. | Жёсткое требование выбрать офис при методе `pvz` (серверная валидация). Выключение — аварийный soft-режим; см. §29.7 в [cdek-mp-checkout-checklist.md](../cdek-mp-checkout-checklist.md). |
| `conditions_step` | вкл. | Шаг с **условиями** (дата/согласие и т.д.). |
| `discount_block_placement` | вкл. | Управление **размещением блока скидок**. |
| `checkout_testing_mode` | выкл. | **Тестовый режим** оплаты (опасно на проде). |
| `admin_live_preview` | вкл. | **Живое превью** в админке, если реализовано. |

**Пример:** чтобы отключить тестовый режим оплаты, снимите `checkout_testing_mode` и сохраните.

## Блок «Step Registry Map» (реестр шагов)

Здесь хранится **снимок конфигурации**:

- список **сценариев** (самовывоз, доставка …);
- **порядок шагов** (`step_order`);
- **описание каждого шага** (`step_definitions`): включён ли шаг, в каких сценариях виден, режим валидации.

**Совет:** не правьте вручную без понимания — ошибка может сломать навигацию. Для маркетинга достаточно менять **тексты на вкладках шагов**; структуру шагов лучше согласовать с разработчиком.
