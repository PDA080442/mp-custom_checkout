# Вкладка «Общие»

Здесь задаётся **основа**: как называется адрес страницы оформления заказа, нужна ли «контрольная точка» входа и как выглядит **экран настроек** в админке (для удобства команды).

---

## Маршруты и доступ

### `route_slug` (slug страницы checkout)

- **Что это:** короткое имя в адресе сайта для **страницы оформления заказа** плагина.
- **Пример:** если указано `mp-checkout`, при **красивых постоянных ссылках** (ЧПУ) адрес может выглядеть так:  
  `https://ваш-сайт.ru/mp-checkout/`
- **По умолчанию:** `mp-checkout`.
- **Как менять:** только латиница, без пробелов, лучше через дефис. Например: `order`, `checkout-mp`, `oformlenie`.
- **Важно:** после смены slug может понадобиться **сохранить настройки постоянных ссылок** в WordPress (Настройки → Постоянные ссылки → «Сохранить»), чтобы правила обновились. Если что-то перестало открываться — сначала проверьте это, потом обращайтесь к разработчику.

#### Связка с корзиной и адресом вида `/zakaz/`

Плагин подменяет **стандартный URL оформления WooCommerce** на ваш кастомный (фильтр `woocommerce_get_checkout_url`). Чтобы кнопка «Оформить заказ» в корзине вела на **ваш** адрес:

1. Во вкладке **Общие** в поле **`route_slug`** укажите тот же slug, что и у страницы оформления, например **`zakaz`** (без слешей).
2. В **WooCommerce → Настройки → Дополнительно** страницу «Оформление заказа» можно оставить любой (ссылки из корзины всё равно пойдут на URL из п.1) или выбрать страницу со slug `zakaz`, если она совпадает с маршрутом.
3. **Настройки → Постоянные ссылки** → нажмите **«Сохранить»** (flush правил).
4. Если раньше была **критическая ошибка** на `/mp-checkout`, после смены slug на `zakaz` открывайте именно **`/zakaz/`**. Убедитесь, что на странице нет конфликтующего старого контента (шорткод `[woocommerce_checkout]` и кастомный шаблон плагина одновременно не нужны — оставьте вывод плагина).

### `success_route_slug` (slug страницы «успех»)

- **Что это:** адрес **страницы благодарности** после оформления (отдельный маршрут плагина).
- **По умолчанию:** `mp-checkout-success`.
- **Пример адреса:** `https://ваш-сайт.ru/mp-checkout-success/`

### `require_entry_gate` (требовать «ворота» входа)

- **Что это:** логический переключатель: можно ли попасть на checkout **только «правильным» путём** (например, с корзины), а не по прямой ссылке.
- **По умолчанию:** включено (`true`).
- **Практика:** если включено, случайный заход по URL без подготовленной сессии может **перенаправить** на корзину или магазин — это защита от пустых/ломаных сценариев. Если отключить, тестировать проще, но выше риск странного поведения для покупателей.

## Брендирование админки (`admin_branding`)

Это **не витрина магазина**, а только экран настроек в WordPress.

| Поле | Зачем | Пример |
|------|--------|--------|
| `title` | Заголовок вверху страницы настроек | `Оформление заказа — настройки` |
| `description` | Подзаголовок-пояснение для команды | `Сценарии доставки, тексты шагов и стили checkout.` |
| `onboarding` | Короткая инструкция «с чего начать» | `Сначала Общие, затем шаги 1–4, потом стили.` |
| `icon` | CSS-класс иконки WordPress (Dashicons) | `dashicons-cart` — корзина; можно другой из набора Dashicons. |
| `accent_color` | Акцентный цвет интерфейса настроек | `#2271b1` (синий в духе WP) |
| `help_style` | Стиль подсказок | `soft` — мягкие; ещё бывают `outline`, `solid` (если доступны в вашей версии). |
| `preview_enabled` | Показывать ли мини-превью бренда в шапке | Вкл./выкл. |

### Цвета интерфейса настроек (`admin_branding.ui_tokens`)

Используются как **фон и границы** панели настроек (не фронт магазина).

- `bg` — фон страницы настроек. Пример: `#ffffff`
- `surface` — фон «карточек». Пример: `#fcfcfc`
- `border` — линии разделителей. Пример: `#dcdcde`
- `text` — основной текст. Пример: `#1f2328`
- `muted` — второстепенный текст. Пример: `#4b5563`
- `risk_bg` / `risk_border` — подсветка **опасных** настроек (например, смена URL). Пример: светло-розовый фон и красноватая рамка.

**Совет менеджеру:** меняйте цвета только если нужно подогнать под корпоративный стиль **внутри админки**. На покупателя это не влияет.

## Типичные сценарии

1. **«Хочу другой адрес checkout»** — меняете `route_slug`, сохраняете, проверяете ссылку на сайте, при необходимости обновляете постоянные ссылки WP.
2. **«Покупатель жалуется, что checkout не открывается с закладки»** — проверьте `require_entry_gate` и сценарий входа с корзины.
3. **«Команда путается в админке»** — заполните `description` и `onboarding` понятными фразами на русском.

---

## Связь с другими вкладками

- **Шаг 1–4** — сами экраны для покупателя (тексты, поля).
- **Служебное** — тестовые режимы и флаги; **Общие** лучше настроить **до** массовых экспериментов на витрине.
