# MP Custom Checkout — Mobile regression matrix (фаза 22.2)

Чеклист для ручной проверки после изменений в мобильной доступности, клавиатуре и производительности. Среды: **iOS Safari** (последняя стабильная), **Android Chrome** (последняя стабильная), ширина **320–430 px** и **768 px** (планшетный порог).

## 1. Фокус и экранные чтецы (Focus + SR)

- [ ] При смене шага фокус попадает на заголовок шага (`#mp-cc-step-heading`), страница не «прыгает» лишний раз (ближний `scrollIntoView`).
- [ ] Регион `#mp-cc-a11y-announcer` объявляет связку «мета шага + заголовок» (кратко, без дублирования при повторном рендере того же шага).
- [ ] У кнопок прогресса есть `aria-controls` на `#mp-cc-step-content-container`, `aria-expanded` соответствует активному шагу, `aria-current="step"` на текущем.
- [ ] Уведомления об ошибках по-прежнему идут через `#mp-cc-notifications` с корректным `role` / `aria-live`.
- [ ] SPA-контейнер `#mp-cc-checkout-app` с `aria-live="off"` не зачитывает каждое обновление DOM целиком.

## 2. Кастомные селекторы (touch + клавиатура)

- [ ] `select.mp-cc-select` (пол, код страны телефона, страна/регион/город адреса): минимальная высота зоны, открывается нативный picker, значение меняется одним касанием.
- [ ] После выбора значения фокус не «теряется» за пределами формы.
- [ ] При ошибке у поля есть согласованный `aria-invalid` и `aria-describedby` на связанный текст ошибки.

## 3. Карточная оплата и поля шлюза (in-card)

- [ ] Регион `#mp-cc-payment-gateway-fields` имеет понятный `aria-label`, доступен для программного фокуса (`tabindex="-1"`) при скролле к ошибке.
- [ ] Радиокнопки способов оплаты озвучиваются как группа; при ошибке «не выбран способ» виден текст `#mp-cc-payment-gateway-err`, радио помечены `aria-invalid` / `aria-describedby`.
- [ ] В режиме `in_card` поля WooCommerce внутри карты прокручиваются так, что нижняя часть не перекрывается клавиатурой полностью (см. п. 5).

## 4. Валидация и скролл к первой ошибке

- [ ] На шаге получателя при «Далее» с пустыми обязательными полями: появляется ошибка, скролл к **первому** невалидному контролу (включая `#mp-cc-payment-gateway-fields` при ошибке оплаты).
- [ ] На мобилке используется `block: "nearest"` (или эквивалент), нет бесконечного smooth-scroll.
- [ ] Если невалидных контролов нет, но шаг невалиден, скролл к первому подходящему заголовку секции (доставка / контакты / оплата).

## 5. Виртуальная клавиатура и перекрытия

- [ ] При открытой клавиатуре на iOS/Android нижний sticky-summary и поля ввода не перекрываются полностью: срабатывает `--mp-cc-keyboard-inset` (через `visualViewport`) + `scroll-margin-bottom` у полей.
- [ ] `scroll-padding-bottom` на `#mp-cc-checkout` помогает не прятать активное поле под нижними панелями.
- [ ] После закрытия клавиатуры верстка возвращается без артефактов (лишние отступы не накапливаются).

## 6. Производительность длинного шага 1 (корзина)

- [ ] Длинный список позиций: скролл остаётся плавным, без заметных фризов при первом проходе.
- [ ] `content-visibility` на списке/карточках не ломает измерение высоты (нет «скачка» при догрузке изображений).

## 7. Кросс-платформа (iOS Safari / Android Chrome)

- [ ] Нет горизонтального overflow на ключевых шагах.
- [ ] Sticky summary и nav не перекрывают друг друга по z-index.
- [ ] Жест «назад» в браузере / свайп не ломает состояние шага (по возможности smoke).

## 8. Регрессия смежных областей

- [ ] Стрелки на кнопках прогресса (desktop rail + mobile rail) по-прежнему двигают фокус.
- [ ] Календарь дат: фокус и `aria-selected` на днях.
- [ ] Карта самовывоза: canvas не перехватывает фокус-кольцо у кнопок рядом.
