# Ручной тест-план: §29.2 UI ПВЗ (карта + fallback)

Предусловия: активны WooCommerce, официальный CDEK (при тесте карты — ключ Яндекс.Карт и наличие `build/service.php` у плагина), в каталоге доставки есть метод `pvz` с тарифом `official_cdek:*`.

1. **`/mp-checkout/` + метод `pvz`** — видна строка ПВЗ (`data-row="pvz"`), кнопка «Выбрать пункт», при `map_ready` — «Выбрать пункт на карте».
2. **Карта** — клик «Выбрать пункт на карте» → модал открывается, контейнер карты не пустой (при рабочем `servicePath` и ключе).
3. **Выбор на карте** — выбрать ПВЗ → модал закрывается, в статусе отображается код; в Network успешный `sub_action=cdek_set_office` (200).
4. **F5** — выбранный офис восстанавливается из flow (`cdek_office_code` в шаге / merged date).
5. **Смена метода** `pvz` → `post_russia` → `pvz` — блок ПВЗ скрывается/появляется; не ломать сценарий почты (визуально и в Network нет лишних смен тарифов почты).
6. **Fallback** — отключить загрузку `cdek-widget` или смоделировать отсутствие `servicePath`: кнопка карты скрыта, «Выбрать пункт» открывает модал со списком `pickupConfig.points`, выбор сохраняет `scenario` как раньше.
7. **Регрессия `post_russia`, `pickup`, `courier`, `krasnoyarsk_delivery`** — без изменений подсказок/тарифов и без ошибок в консоли.

Дополнительно: закрытие модала крестиком / overlay / Escape без выбора пункта на карте — в логах допускается `validation_log` с `event_type` → `pvz_picker_closed_without_selection` (наблюдение, не блокирует «Далее»).
