# Ручной тест-план: §29.2 UI ПВЗ (карта + fallback)

Предусловия: активны WooCommerce, официальный CDEK, заполнен ключ Яндекс.Карт в настройках способа доставки СДЭК; в каталоге доставки есть метод `pvz` с тарифом `official_cdek:*`. Наличие `build/service.php` у плагина **не** обязательно для карты MP.

1. **`/mp-checkout/` + метод `pvz`** — видна строка ПВЗ (`data-row="pvz"`), кнопка «Выбрать пункт», при `map_ready` — «Выбрать пункт на карте».
2. **Карта** — клик «Выбрать пункт на карте» → модал открывается, контейнер карты не пустой при наличии ключа Яндекса и загруженном `window.CDEKWidget` (`service_path` в `mpCcCdekWidget` может быть пустым — типичная сборка плагина).
2a. **`map_ready === true`, `service_path === ''`** — карта открывается, выбор ПВЗ → успешный `cdek_set_office` (паритет с эталонным checkout СДЭК без `servicePath`).
3. **Выбор на карте** — выбрать ПВЗ → модал закрывается, в статусе отображается код; в Network успешный `sub_action=cdek_set_office` (200).
4. **F5** — выбранный офис восстанавливается из flow (`cdek_office_code` в шаге / merged date).
5. **Смена метода** `pvz` → `post_russia` → `pvz` — блок ПВЗ скрывается/появляется; не ломать сценарий почты (визуально и в Network нет лишних смен тарифов почты).
6. **Fallback (нет карты / нет `CDEKWidget`)** — `map_ready === false` или конструктор виджета не загрузился: кнопки «Выбрать пункт» и «Выбрать пункт на карте» открывают модал со списком **офисов СДЭК из `mpCcCdekWidget.offices_json`**; подтверждение вызывает **`mpCcSetCdekOfficeCode`** (как на карте). **Не** показываются точки **`pickupConfig.points`** магазина (раньше ошибочно подставлялись как «ПВЗ»).
7. **Fallback с пустым `offices_json`** — нет города в flow или API не вернул офисы: модал только с текстом «карта недоступна / выберите другой способ доставки» и полем **`reason`** из конфига; без списка и без адреса бутика как ПВЗ.
8. **`map_ready === true` + карта** — по-прежнему модал с картой СДЭК; выбор на карте → `cdek_set_office`.
9. **Регрессия `post_russia`, `pickup`, `courier`, `krasnoyarsk_delivery`** — без изменений подсказок/тарифов и без ошибок в консоли.

Дополнительно: закрытие модала крестиком / overlay / Escape без выбора пункта на карте — в логах допускается `validation_log` с `event_type` → `pvz_picker_closed_without_selection` (наблюдение, не блокирует «Далее»). При переходе на fallback-список ПВЗ возможен **`pvz_map_fallback_to_list`** с **`reason`** / **`subtype`**.

## §29.3 — сохранение офиса и пересчёт доставки

1. **Повтор того же ПВЗ** — второй раз подряд выбрать тот же код (или повторный вызов с тем же значением): лишнего `cdek_set_office` в Network нет (клиентский no-op).
2. **Двойной клик по точке на карте** — не более одного успешного `cdek_set_office` на одну серию выбора (защита `chosenInFlight` в мосте).
3. **Смена ПВЗ в пределах одного города** — два разных кода подряд: оба запроса 200, сводка доставки и `chosen_shipping_methods[0]` согласованы с WC (`official_cdek:*`), без рассинхрона UI.
4. **Ответ 400 `invalid_office_code`** — подставить заведомо неверный код (например через временную правку DevTools в теле запроса): notify на клиенте, локальный откат отображаемого кода, после успешного следующего выбора состояние нормализуется.
5. **Гонка с методом доставки** — во время сохранения метода/тарифа (если успеть открыть карту в другой вкладке редко; проще — смок через отложенный выбор): офис не теряется; после завершения цепочки метода уходит отложенный `cdek_set_office`.
6. **Регрессия `post_russia`** — без изменений поведения относительно до §29.3.

## §29.4 — валидация «Далее» / «Продолжить» без ПВЗ при методе `pvz`

Предусловия: метод `pvz`, тариф выбран, дата выбрана (где требуется), **`cdek_office_code` пуст**.

1. **V2** (`delivery_screen`): «Далее» без выбора офиса — toast с текстом про выбор ПВЗ, экран не меняется; в Network при желании глянуть `validation_log` с ошибкой поля `cdek_office_code` → `pvz_required`.
2. **V2 + офис выбран**: после успешного `cdek_set_office` «Далее» переводит на следующий экран (регрессия перехода).
3. **Legacy multi-step** (`address_delivery`): без офиса клик «Далее» — то же сообщение, подсветка кнопок ПВЗ (`aria-invalid="true"`), переход на следующий шаг не выполняется (если до клиента доходит попытка — `session_set_step` возвращает **422** `pvz_required`).
4. **Сводка «Продолжить»**: на шаге адреса/доставки тот же блокирующий сценарий, что и у «Далее» (общий `moveForward`).
5. **`pickup` / `post_russia`**: без офиса СДЭК переходы не блокируются новой логикой (условие только `shipping_method_id === 'pvz'`).
6. **Подтверждение заказа (V2)**: на последнем экране отправить оплату без офиса (смоделировать расхождение flow vs UI, например два окна) — ответ **422** `pvz_required`, UI возвращает на `delivery_screen`, подсветка ПВЗ.

Примечание к §29.2 п.9: закрытие карты без выбора по-прежнему не сохраняет офис; для метода `pvz` нажатие «Далее» без выбранного офиса теперь блокируется (§29.4).

## §29.5 — сброс ПВЗ при смене города / метода

1. **Краснодар → Москва** при выбранном `pvz` и сохранённом офисе: после подтверждения города карточка ПВЗ без кода; в логах `[pvz] office_invalidated` с `reason=city_change`; после `session_set_answers` пересчёт корзины без «чужого» `official_cdek_office_code` для старого города.
2. **`pvz` → `courier` → снова `pvz`**: офис не подтягивается из flow после промежуточного не-ПВЗ метода (сервер чистит `step_one.cdek_office_code` при записи метода ≠ `pvz`).
3. **`pickup` (магазинный самовывоз)**: сценарий и точки магазина не затрагиваются правкой (меняется только ключ `cdek_office_code` в `step_one`).
4. **`post_russia`**: без изменений поведения тарифов/почты; при смене города контакта при активном `pvz` офис сбрасывается так же, как для любого другого метода с ПВЗ.

## §29.6 — submit order: mp-cc meta и лог shipping line

1. **Заказ через `/mp-checkout/` с `pvz` и выбранным офисом:** в order meta `_mp_cc_cdek_office_code = <code>`, **`_mp_cc_cdek_rate_id = official_cdek:<instance_id>`** из **фактической** shipping line заказа (совпадает с `method_id`/`instance_id` на строке доставки). В логах info: `[pvz] order_shipping_line_persisted` с `office_meta_present=true` (когда на ставке есть meta с `office_code`).
2. **`pvz` выбран, но ставки `official_cdek:*` нет в пакете 0** (несовпадение `wc_rate_id` в каталоге с runtime instance плагина CDEK, ghost rate и т.п.): **submit** не создаёт заказ — ответ **422** `pvz_rate_unavailable`, в логах warning `[pvz] order_shipping_line_missing` с `phase=guard`.
3. **Заказ через `/mp-checkout/` с `courier` или `post_russia`:** ключей `_mp_cc_cdek_office_code` / `_mp_cc_cdek_rate_id` нет; поведение Почты России не регрессирует.
4. **Заказ через `/mp-checkout/` с `pickup` (магазин):** есть `PICKUP_POINT_*` при выборе точки; `_mp_cc_cdek_*` отсутствуют.
5. **Export → import настроек:** метод `pvz` и его тарифы после импорта сохраняют `wc_rate_id` (проверка в админке каталога доставки).
